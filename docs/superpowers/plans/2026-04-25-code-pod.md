# Code-Pod Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Tailscale-attached Arch Linux dev pod with Claude Code, gh, fish + Oh My Fish, OpenSSH, and yay (AUR), backed by two volsynced PVCs (`$HOME` + `~/Code`) and reachable only from the tailnet at `vrtx-pod`.

**Architecture:** Two-stage Containerfile under `build/code-pod/` (stage 1 builds yay-bin from AUR; stage 2 is the final Arch userland with all tools and a minimal sshd). A GitHub Actions workflow scoped to `build/code-pod/**` builds and pushes to `ghcr.io/jsenecal/code-pod`, signs with cosign keyless, and Renovate keeps the digest pinned in the HelmRelease. The cluster manifests live at `kubernetes/apps/default/code-pod/` using bjw-s `app-template`: one Deployment with an `app` container (sshd + Claude Code + dev shell), a `tailscale` sidecar (ephemeral OAuth-derived auth), and a `seed-authorized-keys` initContainer. No Service, no HTTPRoute — the pod is reachable only via Tailscale. Two PVCs are volsynced: `code-pod` (10 GiB `$HOME`, hourly) via the standard component, and `code-pod-workspace` (100 GiB `~/Code`, daily) via hand-written sibling resources.

**Tech Stack:** Arch Linux (`archlinux:base-devel`), OpenSSH, fish + Oh My Fish, GitHub CLI, Node.js + npm, `@anthropic-ai/claude-code`, yay-bin (AUR), Tailscale (ephemeral nodes via OAuth), Kubernetes (bjw-s app-template via Flux Helm), VolSync (restic on NFS), External Secrets Operator + 1Password Connect, GitHub Actions + cosign keyless signing, Renovate.

### Task A3: Create the entrypoint script

**Files:**
- Create: `build/code-pod/rootfs/usr/local/bin/code-pod-entrypoint.sh`

- [ ] **Step 1: Create the entrypoint**

```sh
#!/usr/bin/env bash
set -euo pipefail

# USERNAME is set in the image as ENV (from the Containerfile build arg).
: "${USERNAME:?USERNAME must be set in the image environment}"

# Generate sshd host keys if missing (host keys live on emptyDir, not the home PVC).
ssh-keygen -A

home="/home/${USERNAME}"

# First-run home setup sentinel — only fires on a freshly-provisioned PVC.
if [ ! -e "${home}/.code-pod-initialised" ]; then
  install -d -o "${USERNAME}" -g "${USERNAME}" -m 0700 "${home}/.ssh"
  chown -R "${USERNAME}:${USERNAME}" "${home}"
  touch "${home}/.code-pod-initialised"
  chown "${USERNAME}:${USERNAME}" "${home}/.code-pod-initialised"
fi

exec /usr/sbin/sshd -D -e
```

### Task A4: Write the Containerfile

**Files:**
- Create: `build/code-pod/Containerfile`

- [ ] **Step 1: Create the multi-stage Containerfile**

```dockerfile
# syntax=docker/dockerfile:1.7
# Stage 1: build yay-bin from AUR (kept out of the final layer).
FROM docker.io/library/archlinux:base-devel AS aur-build

RUN pacman -Syu --noconfirm git \
 && useradd -m -G wheel builder \
 && echo 'builder ALL=(ALL) NOPASSWD: /usr/bin/pacman' > /etc/sudoers.d/builder

USER builder
WORKDIR /home/builder

RUN git clone --depth=1 https://aur.archlinux.org/yay-bin.git \
 && cd yay-bin \
 && makepkg --noconfirm -s

# Final image: clean Arch, dev tooling, sshd, our user.
FROM docker.io/library/archlinux:base-devel AS final

ARG USERNAME=jsenecal
ARG UID=1000
ARG GID=1000
ENV USERNAME=${USERNAME}

RUN pacman -Syu --noconfirm \
      openssh git base-devel sudo fish curl wget unzip jq less \
      ripgrep fd bat eza htop rsync tmux nodejs npm github-cli \
      python python-pip ca-certificates tzdata \
 && pacman -Scc --noconfirm

COPY --from=aur-build /home/builder/yay-bin/yay-bin-*.pkg.tar.zst /tmp/
RUN pacman -U --noconfirm /tmp/yay-bin-*.pkg.tar.zst \
 && rm -f /tmp/yay-bin-*.pkg.tar.zst

# Drop-in config files (sshd, sudoers, fish, profile).
COPY rootfs/ /

RUN groupadd -g ${GID} ${USERNAME} \
 && useradd -m -u ${UID} -g ${GID} -G wheel -s /usr/bin/fish ${USERNAME} \
 && chmod 0440 /etc/sudoers.d/wheel-pacman

# Install Claude Code globally (lives in /usr/local, not on the home PVC).
RUN npm config --global set prefix /usr/local \
 && npm install -g @anthropic-ai/claude-code

# Oh My Fish as the user, into the user's home (this layer is preserved into
# the image; on first pod boot the home PVC mount will shadow it, and the
# entrypoint's first-run sentinel will let omf bootstrap from the user
# manually if they ever want a fresh install).
USER ${USERNAME}
WORKDIR /home/${USERNAME}
RUN curl -fsSL https://raw.githubusercontent.com/oh-my-fish/oh-my-fish/master/bin/install -o /tmp/omf-install \
 && fish /tmp/omf-install --noninteractive --yes \
 && rm -f /tmp/omf-install

USER root
WORKDIR /

# Entrypoint script perms set explicitly because git mode != image mode is brittle.
RUN chmod 0755 /usr/local/bin/code-pod-entrypoint.sh

EXPOSE 22

LABEL org.opencontainers.image.source="https://github.com/jsenecal/vrtx-cluster" \
      org.opencontainers.image.title="code-pod" \
      org.opencontainers.image.description="Tailscale-attached Arch dev pod with Claude Code"

ENTRYPOINT ["/usr/local/bin/code-pod-entrypoint.sh"]
```

# code-pod

Container image for the Tailscale-attached Arch dev pod under `kubernetes/apps/default/code-pod/`.

## Build

```bash
cd build/code-pod
docker buildx build --load -t code-pod:dev .
```

```bash
docker run -d --name code-pod-test -p 12222:22 code-pod:dev
docker exec -u jsenecal code-pod-test fish -c 'claude --version; gh --version; yay --version'
```

To ssh in, copy a pubkey into `/home/jsenecal/.ssh/authorized_keys` (mode 0600, owner `jsenecal`).

## What's in the image

Stage 1 (`aur-build`) builds `yay-bin` from AUR with a disposable `builder` user. Only the resulting `.pkg.tar.zst` crosses into stage 2.

Stage 2 (`final`) installs the pacman package set, copies the AUR yay package and `pacman -U`s it, drops in `rootfs/`, creates `${USERNAME}` (UID `${UID}`, in `wheel`, shell `/usr/bin/fish`), `npm install -g @anthropic-ai/claude-code`, runs the Oh My Fish installer non-interactively as the user, sets the entrypoint.

Runtime (`code-pod-entrypoint.sh`) generates sshd host keys, runs a first-run home-PVC sentinel to set ownership and create `~/.ssh`, then `exec`s `sshd -D -e`.

## CI

`.github/workflows/code-pod-image.yaml` builds on PRs (no push) and pushes + cosigns on `main`. Trigger manual rebuilds with the workflow's `workflow_dispatch`.

  IMAGE: ghcr.io/${{ github.repository_owner }}/code-pod

jobs:
  build:
    name: Build
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Checkout
        uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6.0.2

      - name: Hadolint
        uses: hadolint/hadolint-action@54c9adbab1582c2ef04b2016b760714a4bfde3cf # v3.1.0
        with:
          dockerfile: build/code-pod/Containerfile
          failure-threshold: warning

      - name: Set up Buildx
        uses: docker/setup-buildx-action@e468171a9de216ec08956ac3ada2f0791b6bd435 # v3.11.1

      - name: Build (no push)
        uses: docker/build-push-action@263435318d21b8e681c14492fe198d362a7d2c83 # v6.18.0
        with:
          context: build/code-pod
          file: build/code-pod/Containerfile
          push: false
          load: true
          tags: code-pod:ci
          cache-from: type=gha,scope=code-pod
          cache-to: type=gha,scope=code-pod,mode=max

      - name: Trivy scan
        uses: aquasecurity/trivy-action@dc5a429b52fcf669ce959baa2c2dd26090d2a6c4 # v0.32.0
        with:
          image-ref: code-pod:ci
          severity: HIGH,CRITICAL
          ignore-unfixed: true
          exit-code: "1"
          trivyignores: build/code-pod/.trivyignore

  push:
    name: Push & Sign
    needs: build
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
      id-token: write
    outputs:

      - name: Checkout
        uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6.0.2

      - name: Set up Buildx
        uses: docker/setup-buildx-action@e468171a9de216ec08956ac3ada2f0791b6bd435 # v3.11.1

      - name: Login to ghcr
        uses: docker/login-action@184bdaa0721073962dff0199f1fb9940f07167d1 # v3.5.0
        with:
          registry: ghcr.io
          username: ${{ github.repository_owner }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build & push
        id: build
        uses: docker/build-push-action@263435318d21b8e681c14492fe198d362a7d2c83 # v6.18.0
        with:
          context: build/code-pod
          file: build/code-pod/Containerfile
          push: true
          tags: |
            ${{ env.IMAGE }}:main
            ${{ env.IMAGE }}:sha-${{ github.sha }}
            ${{ env.IMAGE }}:latest
          cache-from: type=gha,scope=code-pod
          cache-to: type=gha,scope=code-pod,mode=max
          labels: |
            org.opencontainers.image.source=https://github.com/${{ github.repository }}
            org.opencontainers.image.revision=${{ github.sha }}
            org.opencontainers.image.created=${{ github.event.repository.updated_at }}

        if: ${{ contains(needs.*.result, 'failure') }}

### Task C1: Create the Tailscale OAuth client

- [ ] **Step 1: Create OAuth client**

Open the Tailscale admin console → Settings → OAuth clients → "Generate OAuth client".
- Description: `code-pod`
- Scope: check `auth_keys` (write). This is the minimum-privilege scope for minting auth keys via the `tskey-client-<id>-<secret>` URL pattern. Do NOT grant `devices:core:write` unless you have a reason — it's broader than needed.

## Troubleshooting

If `code-pod-tailscale-secret` is empty / sidecar errors with "no auth key":
- Confirm the 1Password item `code-pod` has fields `TS_OAUTH_CLIENT_ID` and `TS_OAUTH_CLIENT_SECRET` (uppercase, exact names).
- `kubectl -n default describe externalsecret code-pod-tailscale` for ESO sync errors.

If the pod's `seed-authorized-keys` initContainer succeeds but ssh still rejects you:
- `kubectl -n default exec deploy/code-pod -c app -- cat /home/jsenecal/.ssh/authorized_keys` to confirm the file content matches your laptop's pubkey exactly.
- Check `kubectl -n default logs deploy/code-pod -c app | tail -50` for sshd's per-connection diagnostic output (`-e` sends to stderr).

If MagicDNS doesn't resolve `vrtx-pod`:
- Confirm MagicDNS is enabled in Tailscale admin → DNS.
- Use the IP shown in Tailscale admin for the node directly.

If the pod can't bind the home PVC because volsync's restore step never finishes:
- `kubectl -n default get replicationdestination code-pod-dst -o yaml | yq '.status'` to see if the trigger fired.
- On a fresh deploy with no prior backup, `manual: restore-once` is a no-op (no snapshot to restore), and the PVC binds empty — this is the expected first-time behavior.
